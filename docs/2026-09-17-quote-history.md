# 报价历史快照、预览与应用

## 原有能力与编号

报价列表的 V 是记录版本号，保存、发送、归档、恢复等更新会递增，用于并发冲突检测，并非已保存历史快照的数量。原功能只在发送时留下不可变快照，历史弹窗只显示快照和发送记录，无法预览或应用。

本次历史快照以 R 编号展示，附记录 V、留存时间、操作人和事件（首次保存、编辑保存、编辑前留存、发送时留存）。已有发送快照不改编号。

## 新行为

- 新版报价首次保存及每次编辑保存，在同一数据库事务中记录完整快照。编辑旧记录前，如果当前 V 未有快照，先留存编辑前内容。失败、版本冲突会回滚，不留失败快照。
- 复用 `quote_revisions`，无需迁移或新增表。不捕获未保存的输入，也无法恢复升级前未曾留存的编辑过程。旧 `quotes` 格式仍沿用兼容读写，本次保存历史针对 `commerce_quotes`。
- 新增只读 `GET /api/v1/staff/quotes/{quote_id}/history/{revision_id}`，校验员工身份、报价归属和快照归属。管理员可访问全局，业务员只能访问自己的报价；客户不能访问。
- 预览历史标题、客户联系资料、币种、项目/配置、数量、单价、小计及合计。内容来自不可变快照，不从当前目录重新计算。
- “应用到编辑器”载入历史标题、客户资料、语言、币种及项目，保留当前报价身份、来源和最新版本号。需要手动保存才生效，沿用原保存验证、权限、审计及版本冲突保护。应用前若报价已更新，要求重新打开预览；已归档报价只能预览。
- 应用不自动发送，不修改已有快照或客户收到的版本。保存后产生新快照。

## 验证

- `tests/test_quote_history_snapshots.py`：隔离迁移数据库，验证保存/应用、发送快照不变、冲突不增快照、旧记录编辑前留存、两名业务员/管理员/客户权限、跨报价快照拦截及归档只读。
- `tests/browser_quote_history.cjs`：全部请求模拟，验证列表、预览明细、应用参数、并发更新拒绝和归档禁用；应用前没有写请求。
- 前端契约回归及原归档/恢复/发送历史集成测试。

## 发布

仅本机实现与隔离测试，未部署 NAS、未改动正式业务数据。当前 8082 代理 NAS 旧 API 时，新界面可显示旧历史列表，预览会提示更新后端。发布时先更新兼容 API，再发布前端。无自动迁移历史编辑记录，无自动发送。
