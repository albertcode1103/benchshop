# BOTEN 业务内容聚合与排序规范

版本：1.0  
适用范围：用户购物车、后台分享详情、询价详情、报价查看与编辑、相关 PDF 数据准备。

## 1. 目标

同一份业务内容无论从购物车、分享码、询价或报价进入，都必须保持相同的信息顺序、分组名称和数量口径。界面可以因操作目的不同而使用卡片、抽屉、弹窗或表格，但不得重新定义业务排序。

## 2. 一级聚合顺序

固定顺序如下，不受创建语言、当前语言、名称字母或接口返回顺序影响：

1. 设备
2. 维修工具
3. 设备附件

数量为零的一级分组不渲染，不保留空标题或空容器。

## 3. 设备规则

- 每份已保存设备配置是一个独立设备单元，不把两台同型号设备合并。
- 设备按照加入购物车或业务快照中的先后顺序排列，标记为“设备 1、设备 2……”；后续分享、询价、报价和 PDF 保持该序号。
- 每台设备内部顺序固定为：型号与名称、颜色、电机、电源、通道、可选配置。
- 可选配置按后台分类顺序排列；分类内按后台配置顺序排列。
- 报价中的设备基础价格行必须与该设备的附加费、可选配置保持在同一设备组内。

## 4. 工具与附件规则

- 所有维修工具聚合为一个“维修工具”分组；所有设备附件聚合为一个“设备附件”分组。
- 不按加入购物车时间排序。优先使用后台目录分类顺序和项目顺序；缺少排序元数据时使用编号，其次名称，最后使用原始顺序保证稳定。
- 相同业务项目只显示一行，以数量字段表示件数；不得用重复行表达数量。
- 分组标题显示项目种类数，汇总信息显示数量合计。二者不得混用。

## 5. 数量口径

- 设备：按独立设备配置计“台”。
- 工具和附件：按各行 `quantity` 求和计“件”。
- “项目数”只表示不同条目数量。
- 摘要中零数量分组不显示，例如没有附件时只显示“2 台设备 · 5 件工具”。

## 6. 失效与历史数据

- 分享、询价和报价属于业务快照。目录项目后续停用或删除时，历史快照不得被静默移除。
- 能够识别失效状态时，在原位置显示“已失效”标记；仍显示快照中的编号、名称和数量。
- 无法解析类型的历史条目放在末尾的“其他项目”组，并记录诊断信息，不得归入设备组。

## 7. 中英文规则

- 排序依据使用稳定 ID、排序值和编号，不使用翻译后的显示名称。
- 中文和英文只改变标题与内容文本，不改变设备序号、分组顺序和数量。
- 英文缺失不得自动回退显示中文；数据维护界面应提示补齐英文内容。

## 8. 实现约束

- 后端保存分享和询价快照时使用统一的规范顺序。
- 后台前端使用统一的 `canonicalCommerceItems` 和 `aggregateCommerceItems` 处理函数，不允许分享、询价、报价分别编写独立排序规则。
- PDF 生成前必须再次使用服务端规范顺序，不能依赖浏览器传入顺序。
- 分享配置 PDF 在用户端和管理后台均不得显示价格；只有正式报价单 PDF 可以显示价格。
- 新增业务类型时必须更新本规范、类型优先级映射和回归测试。

## 9. 验收示例

输入顺序为“附件 A、设备 B、工具 C、设备 A、工具 A”时，展示顺序必须为：

1. 设备 B
2. 设备 A
3. 维修工具：工具 A、工具 C（依据后台目录顺序或编号排序）
4. 设备附件：附件 A

用户购物车、后台分享详情、询价详情、报价编辑和 PDF 的一级顺序必须一致。
